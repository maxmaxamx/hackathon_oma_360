# OMA 360

Сервис обустройства комнаты под ключ: клиент описывает помещение и бюджет,
нейросеть задаёт 5 уточняющих вопросов, считает материалы, подбирает реальные
товары из каталога OMA и собирает три пакета комплектации. После выбора пакета
клиент получает визуализацию, план из 10 этапов, назначенного прораба и итоговую
смету. Заказ ведётся в кабинетах клиента и прораба, оплата этапов имитируется
через Escrow.

## Стек

- Next.js 15 (App Router) + TypeScript
- Tailwind CSS 4, дизайн-система из макетов (`stitch_oma_360_room_renovator`)
- Prisma + SQLite
- Сессии: httpOnly JWT-cookie (jose), пароли — bcrypt
- AI: OpenAI-совместимый шлюз, custom base URL
- Каталог: неофициальный поиск OMA (`search-api.md`) с обходом HosterGuard/CSRF

## Быстрый старт

```bash
npm install
npx prisma db push
npm run db:seed
npm run dev
```

Откройте http://localhost:3000.

## Переменные окружения

Скопируйте `.env.example` в `.env`.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | SQLite, по умолчанию `file:./dev.db` |
| `AUTH_SECRET` | секрет подписи сессионных JWT |
| `AI_BASE_URL` | база OpenAI-совместимого шлюза, например `https://opencode.ai/inference/openai/v1` |
| `AI_API_KEY` | ключ шлюза; если пуст — AI-шаги работают на детерминированных fallback |
| `AI_TEXT_MODEL` | текстовая модель, например `deepseek-v4.1-flash` |
| `AI_IMAGE_MODEL` | модель генерации изображений; для DeepSeek пустая — preview отключён |
| `OMA_CITY_ID` | город каталога, по умолчанию `8019` (Минск) |
| `OMA_LOCATION_ID` | склад, по умолчанию `432550` |
| `USE_MOCK_CATALOG` | `true` только для офлайн-разработки; по умолчанию `false` |

Шлюз должен поддерживать:

- `POST {AI_BASE_URL}/chat/completions` с `response_format: json_object`;
- `POST {AI_BASE_URL}/images/generations` с `response_format: b64_json`.

Без ключа сервис полностью работоспособен: вопросы, стилевые предпочтения и план
берутся из шаблонов, вместо визуализации показывается аккуратный плейсхолдер.

### Если AI не работает

Проверка конфигурации и доступности модели:

```bash
npm run ai:check
```

Типовые ответы шлюза:

- `402 Insufficient account funds` — на счёте OpenCode Go недостаточно средств.
  Нужно пополнить баланс либо использовать бесплатную модель, когда доступна её
  квота.
- `429 FreeUsageLimitError` — исчерпан лимит бесплатной модели.
- `400 Model is unavailable` — неверный ID модели для этого шлюза.
- `404` — `AI_BASE_URL` не указывает на OpenAI-совместимый `/v1`.
- `AI_IMAGE_MODEL` пустой — генерация изображений отключена. DeepSeek умеет
  только текст, для preview нужна отдельная image-модель и её ID в env.

Ошибки шлюза пишутся в консоль сервера с кодом и телом ответа. Если AI недоступен,
смета и план всё равно формируются на встроенных fallback-сценариях.

## Пользовательский сценарий

1. Лендинг → регистрация с ролью «Клиент» или «Прораб».
2. Шаг 1 — тип комнаты, площадь, потолки, описание, бюджет.
3. Шаг 2 — 5 AI-вопросов; ответы сохраняются в БД.
4. Расчёт — фоновая задача ищет товары в каталоге OMA, считает объёмы с запасом
   7%, округляет до кратности упаковки и собирает пакеты «Эконом / Базовый / Люкс».
5. Шаг 3 — выбор пакета и полная спецификация с реальными ценами.
6. Шаг 4 — AI-визуализация (асинхронно), план из 10 этапов, прораб, итог.
7. «Оплатить» → заказ переходит в работу, средства «замораживаются» в Escrow.
8. Клиент следит за этапами, материалами, счётом и общается с прорабом в чате.
9. Прораб отмечает этапы: товары этапа становятся «Куплено», часть Escrow
   освобождается. После всех 10 этапов доступна кнопка «Завершить заказ».

## Расчёт

- Геометрия: комната аппроксимируется прямоугольником 4:3, периметр выводится из
  площади; площадь стен = периметр × высота − проёмы.
- Объёмы: пол +7%, плитка +10%, краска в 2 слоя, штукатурка 8 кг/м², стяжка
  20 кг/м², подложка и плинтус по площади/периметру.
- Количество округляется вверх до `catalog.cart.inc` (кратность закупки OMA).
- Стоимость услуг прораба = 50% стоимости товаров.
- `итог = товары × 1.5`; бюджеты 10 этапов включают материалы и распределённые
  работы, их сумма равна итогу.

## Каталог OMA

`lib/oma/client.ts` реализует полный цикл из `search-api.md`:

1. GET главной страницы, извлечение `hg-security` из скрипта HosterGuard.
2. Повторный запрос с cookie `hg-client-security` + `hg-security`.
3. Извлечение `bitrix_sessid` и `PHPSESSID` (cookie `deleted` игнорируются).
4. Поиск через `/api-v2/catalog/products/search/fast` с CSRF-заголовком.
5. При `invalid_csrf`/`403`/повторной верификации сессия обновляется и запрос
   повторяется. Результаты кэшируются на 30 минут, запросы сериализуются.

Если каталог недоступен целиком, расчёт завершается ошибкой с кнопкой
«Повторить» — данные шага 1 и ответы не теряются. Выдуманные товары не
подставляются.

## Docker

Соберите и запустите контейнер:

```bash
cp .env.example .env   # заполните AUTH_SECRET, AI_*, OMA_*
docker compose up -d --build
```

Приложение откроется на http://localhost:3000.

Что настроено:

- многоступенчатая сборка Next.js на `node:22-bookworm-slim`;
- SQLite хранится в именованном volume `oma360-data` (`/app/data/oma.db`);
- сгенерированные изображения — в volume `oma360-generated`
  (`/app/public/generated`);
- при старте контейнера схема применяется через `prisma db push`, а демо-прорабы
  создаются только если база пустая;
- контейнер работает от пользователя `node`, есть healthcheck;
- переменные AI и OMA берутся из `.env` через `env_file`.

Полезные команды:

```bash
docker compose logs -f app     # логи
docker compose down            # остановить
docker compose down -v         # остановить и удалить базу/картинки
npm run docker:up              # собрать и запустить
```

Без Docker Compose:

```bash
docker build -t oma360 .
docker run -p 3000:3000 --env-file .env \
  -e DATABASE_URL=file:/app/data/oma.db \
  -v oma360-data:/app/data \
  -v oma360-generated:/app/public/generated \
  oma360
```

Важно: для реального деплоя смените `AUTH_SECRET` и не коммитьте `.env` в
репозиторий.

## Ограничения демо

- Реальной оплаты нет: кнопка «Оплатить» лишь включает Escrow-учёт.
- Визуализация генерируется асинхронно; при отсутствии ключа показывается
  плейсхолдер с дисклеймером.
- Поиск OMA неофициальный и может быть ограничен WAF; предусмотрены повторы и
  понятные ошибки.
- Контактные данные — email и встроенный чат; другие каналы связи в сервисе не
  используются.
